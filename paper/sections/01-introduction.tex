How should web infrastructure be designed when the traffic it serves is no longer
mostly human?
Operators already treat automated traffic by its class: content-delivery networks let site
owners allow or block search crawlers, training crawlers and AI agents as separate
categories~\cite{cloudflare2026options}, and the IETF is standardising how automated
clients sign their requests and how sites state their
preferences~\cite{ietf-webbotauth,ietf-aipref-vocab}.
These mechanisms rest on an assumption that can be measured: that a class of traffic has a
cost, so that knowing the class tells the operator what admitting more of it will do.
We ask whether the cost of a class is a fixed property of the class, or whether it depends
on the state of the shared cache and on the other traffic that shares it.

The question sits on a chain that we examine link by link.
More automated traffic changes the composition of what a cache sees; the composition
changes how the cache behaves for each class; that behaviour sets the work that reaches the
origin; and a policy that assigns a cost to a class may be wrong if it ignores the state
that sets that work.
We measure the middle links on a testbed with a Varnish cache in front of a
database-backed site, where three classes share the cache: a human class with Zipf-like
popularity, an exhaustive class that traverses the corpus like a crawler, and an agentic
class that reads short sessions of related pages (\cref{sec:method}).
The quantity we measure is the \emph{load-marginal} cost of a class: the origin requests
caused by one more request of that class, when its offered rate increases while the others
stay fixed.\claim{A1}
We vary one property of the agentic class at a time, in particular its \emph{reachable
set}, the set of objects its requests can touch.\claim{A1}

The main result is that the marginal cost of a class changes sign with its reachable
set.\claim{A1}
With the same label, volumes, cache and corpus, one more agentic request costs $-0.035$
origin requests when the reachable set is 0.19 times the cache capacity, $+0.143$ at 0.58
times and $+0.421$ at 1.90 times (\cref{sec:r-sign}).\claim{A1}
A negative marginal is not a saving: at the smallest reachable set, adding the agentic
class from 0 to 36 requests per second still costs $1.10$ origin requests per
second.\claim{A9}
The other two classes behave differently: the per-request cost of the exhaustive class is
flat when its own rate varies, and neither class moves much when the agentic rate
grows.\claim{A2}\claim{A7}
The measured cost of a class also depends on the others: how much the agentic reachable set
overlaps with the human popular head changes its measured cost by 0.80 to 0.93 origin
requests per second, and its miss ratio measured alone does not predict the one in the
mixture.\claim{A3}\claim{C4}
The human class pays for a wider agentic reachable set through origin load rather than
lost cache hits: its tail latency rises while its miss ratio barely
moves.\claim{B5}
At the operating point we measured, blocking the agentic class in addition to the
exhaustive one costs served requests without a latency difference that we can
measure.\claim{A4}

Taken together, these measurements support one statement: a traffic class does not have a
stable marginal cost independent of the state of the shared cache.\claim{D1b}
In our testbed this holds for the agentic class; the exhaustive class, varied on its own
volume, stays close to a constant, so the label guarantees stability in neither
direction.\claim{D1b}\claim{A7}
As a design implication rather than a validated technology, if infrastructure wants to make
class-sensitive decisions, identity alone can be insufficient, because the marginal
effect of a class is state-dependent.\claim{D3}
Blocking the exhaustive class by its identity lies on the frontier of served work and human
latency that we sampled; we did not test policies that ignore identity.\claim{D2}
The further implications we draw, again as implications, are that infrastructure would
need to observe the width of a class's set of requested objects, an estimate of its
marginal cost in the current cache state, and its effect on the other
workloads.\claim{D4}\claim{D5}\claim{D6}

The change of sign is consistent with the classical characteristic-time theory of LRU
caches: computed after the fact with the access distribution of our generator, that theory
reproduces the measured values (\cref{sec:m-tc}).\claim{B7}
Our contribution is therefore not a new law of caching.
It is to show, at the origin, that the label of a class does not determine its marginal
cost, and to quantify how much it varies; to keep the marginal apart from the net effect of
a class; to expose the overlap between classes as a confounder of the measured cost; and to
show how the cost reaches human traffic through origin load.\claim{A1}\claim{A9}\claim{A3}\claim{B5}

This paper makes three contributions.
\begin{itemize}
\item A measurement of the load-marginal origin cost of three coexisting classes of web
  traffic, with the reachable set of one class as the manipulated variable, showing a
  change of sign under a fixed label and separating it from the net effect of the class
  (\cref{sec:r-sign,sec:r-asymmetry}).\claim{A1}\claim{A2}\claim{A9}
\item A measurement confounder, quantified: the overlap between the reachable sets of
  different classes changes the cost measured for a class, a choice that experiments on
  mixed traffic easily leave implicit (\cref{sec:r-overlap}).\claim{A3}
\item A statement of what infrastructure would need to know beyond identity, set against
  the closest existing lines of work, as implications and open questions rather than a
  component (\cref{sec:implications}).\claim{D4}\claim{D5}\claim{D6}
\end{itemize}

The configurations behind the main results were measured again under pre-registered
protocols, and a simulator of our load generator found an artefact in it, which a
pre-registered rerun corrected (\cref{sec:m-classes,sec:m-prereg}).\claim{A1}\claim{A9}
A public honeypot places the synthetic agentic class but does not validate it: by the
number of distinct objects requested within a short window, our smallest reachable set is
close to the agentic clients we observed, while their requests are far less contiguous
than our sessions.\claim{C3}\claim{C5}
