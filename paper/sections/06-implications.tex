\paragraph{As-is.}
Today, decisions on automated traffic use its identity and its load: operators allow or
block declared or verified classes~\cite{cloudflare2026options,ietf-webbotauth}, and
admission control reacts to load or
latency~\cite{cho2020breakwater,zhou2018dagor,cho2023protego,park2024topfull}
(\cref{sec:background,sec:rw}).\claim{D1}
These mechanisms rest on an assumption that can be measured: that a class of traffic has a
cost, so that knowing the class tells the operator what admitting more of it will
do.\claim{D1}
Our measurements show that a traffic class does not have a stable marginal cost
independent of the state of the shared cache.\claim{D1b}
In our testbed this holds for the agentic class: its marginal cost changes sign with its
reachable set, and its measured cost depends on the classes it shares the cache with.
The exhaustive class, varied on its own volume, stays close to a constant, so the label does
not guarantee stability either way (\cref{sec:results}).\claim{D1b}\claim{A1}\claim{A3}\claim{C4}\claim{A7}

\paragraph{Transition.}
Everything that follows is a design implication that we draw from these measurements;
none of it is a validated technology.\claim{D3}
Identity remains an input, but if infrastructure wants to make class-sensitive decisions,
identity alone can be insufficient, because the marginal effect of a class is
state-dependent.\claim{D1}\claim{D3}
At the knee of the testbed, blocking the exhaustive class by its identity lies on the
empirical work/latency frontier sampled at that operating point; we did not test policies
that ignore identity (\cref{sec:r-frontier}).\claim{D2}
A policy that knows only that traffic is agentic, however, does not necessarily hold enough
information to estimate its marginal impact,
since under the same label the marginal cost ranged from $-0.035$ to $+0.421$ origin
requests per request (\cref{sec:r-sign}).\claim{D1}
The first quantity to place beside the label, and the one with the strongest support, is how
wide a class's set of requested objects is, since the width of the reachable set alone
changed the sign of the marginal cost.\claim{D4}\claim{A1}
It is observable: the windowed working set is the counterpart of the reachable set in
request logs, and we computed it over a short window for the clients of our honeypot
(\cref{sec:m-honeypot}).\claim{D4}\claim{C3}

\paragraph{To-be: properties, not architecture.}
The further implications say what infrastructure would need to know, not how to build
it.\claim{D5}\claim{D6}
A useful infrastructure would need an estimate of the marginal cost of the class in the
current state of the shared cache, because in the primary design one blocked exhaustive
request frees about 0.84 origin requests and one agentic request about
0.16.\claim{D5}\claim{A5}
It should also know the effect of a class on the other workloads, because the human p99
rose by 26.7\,ms while the human miss ratio changed only by a factor of 1.07
(\cref{sec:m-human}).\claim{D6}\claim{B5}
As a map of the questions that a class-sensitive decision would have to answer, and not as
an architecture, these implications line up in one chain:\claim{D3}
\begin{center}\small
\textsc{class} $\rightarrow$ \textsc{state} $\rightarrow$ \textsc{cost} $\rightarrow$
\textsc{externality} $\rightarrow$ \textsc{decision}
\end{center}
The class says who the traffic is, which is what classification provides today; the state
says how the class behaves against the shared cache, for example how wide its windowed
working set is; the cost is what the next request of the class costs now; the externality
is who pays for it among the other workloads; and the decision is whether to admit, defer,
prioritise or isolate the class.\claim{D3}\claim{D4}\claim{D5}\claim{D6}
Our measurements bear on the state, cost and externality links; at the decision step,
blocking and deferring lie on one frontier in our testbed, and isolating the agentic class
would remove a measured benefit.\claim{A6}\claim{D8}
\Cref{tab:bridge} restates these implications as three properties, P1 to P3, and sets
each one against the evidence that motivates it, the decision it would enable, the closest
existing line of work and where that line of work falls short for our evidence.\claim{D4}\claim{D5}\claim{D6}

\subsection{Open questions}\label{sec:open}
Two questions remain open, and we state them as such.
The first is how to estimate P2 online, without the controlled experiments we used to
measure it; capacity-marginal estimators such as miss-ratio curves answer a different
question (\cref{sec:rw}).\claim{D5}
Interpretive, post hoc: as an implication, a classical model may be enough for the estimate
itself, since, fed with the access distribution of the class, the characteristic-time
approximation reproduces the values we measured (\cref{sec:m-tc}).\claim{B7}\claim{D5}
What remains open is whether that distribution can be estimated online from request logs,
where the contiguity of real clients differs from that of our sessions
(\cref{sec:limitations}).\claim{D5}\claim{C5}
The second is the weakest of our implications: that infrastructure would also need the
state of the shared cache and the pressure on resources, which our evidence supports only
indirectly; load- and latency-driven admission
control~\cite{cho2020breakwater,zhou2018dagor,cho2023protego,park2024topfull} is the
closest line of work, and we did not measure this property.\claim{D7}

% Phase 2 of the simulator: rows S2-S6 of claims.md v3.8 only; SIMULATO, never MISURATO.
The simulator gives a first, simulated answer to whether these properties are tied to LRU
(\cref{sec:m-sim}).\claim{S2}
In the simulator the dependence on the reachable set holds for most policies and session
models, and the net effect of adding the agentic class changes sign with the
policy.\claim{S2}\claim{S5}
If this holds on real systems, the cost of a class depends on the state and on the policy of
the cache, and an estimate of P2 would have to be made for the cache as it is
configured.\claim{S2}\claim{S5}\claim{D5}

We did not find prior work that jointly measures, in one shared cache, the marginal origin
cost of one more request of a class, its dependence on the width of the class's reachable
set, the overlap between classes as a controlled variable, and the effect on the tail
latency of the other classes.\claim{D9}
Whether admission, placement and priority can move from deciding on identity to deciding
on state and cost is the question these implications open.\claim{D1}\claim{D3}
