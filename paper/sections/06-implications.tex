A traffic class does not have a stable marginal cost independent of the state of the
shared cache.\claim{D1b}
In our testbed this holds for the agentic class: its marginal cost changes sign with its
reachable set, and its measured cost depends on the classes it shares the cache with.
The exhaustive class, varied on its own volume, stays close to a constant, so the label does
not guarantee stability either way (\cref{sec:results}).\claim{D1b}\claim{A1}\claim{A3}\claim{C4}\claim{A7}
Everything that follows is a design implication that we draw from these measurements;
none of it is a validated technology.\claim{D3}

\paragraph{Classification during the transition.}
If infrastructure wants to make class-sensitive decisions, identity alone can be
insufficient, because the marginal effect of a class is state-dependent.\claim{D1}\claim{D3}
Our data imply that classification remains necessary: at the knee of the testbed,
blocking the exhaustive class by its identity lies on the empirical work/latency frontier
sampled at that operating point (\cref{sec:r-frontier}).\claim{D2}
They also imply that it is not necessarily sufficient: a policy that knows only that
traffic is agentic does not necessarily hold enough information to estimate its marginal
impact, since under the same label the marginal cost ranged from $-0.035$ to $+0.421$
origin requests per request (\cref{sec:r-sign}).\claim{D1}

\paragraph{Three quantities beside the label.}
As design implications, three quantities would complement the class label.\claim{D4}\claim{D5}\claim{D6}
The first implication, and the one with the strongest support, is that infrastructure
should be able to observe or derive how wide a class's set of requested objects is,
since the width of the reachable set alone changed the sign of the marginal
cost.\claim{D4}\claim{A1}
What infrastructure can observe is the windowed working set, the counterpart of the
reachable set in request logs: we computed it over a short window for the clients of our
honeypot (\cref{sec:m-honeypot}).\claim{D4}\claim{C3}
The second implication is that it should know the marginal cost of the class in the
current state of the shared cache, because at the operating point of the frontier one
blocked exhaustive request frees about 0.82 origin requests and one agentic request about
0.10.\claim{D5}\claim{A5}
The third implication is that it should know the effect of a class on the other
workloads, because the human p99 rose by 26.7\,ms while the human miss ratio changed only
by a factor of 1.07 (\cref{sec:m-human}).\claim{D6}\claim{B5}

\subsection{Open questions}\label{sec:open}
Two questions remain open, and we state them as such.
The first is how to estimate P2 online, without the controlled experiments we used to
measure it; capacity-marginal estimators such as miss-ratio curves answer a different
question (\cref{sec:rw}).\claim{D5}
The second is the weakest of our implications: that infrastructure would also need the
state of the shared cache and the pressure on resources, which our evidence supports only
indirectly; load- and latency-driven admission
control~\cite{cho2020breakwater,zhou2018dagor,cho2023protego,park2024topfull} is the
closest line of work, and we did not measure this property.\claim{D7}

% Phase 2 of the simulator: rows S2-S6 of claims.md v3.8 only; SIMULATO, never MISURATO.
The simulator gives a first, simulated answer to whether these properties are tied to LRU
(\cref{sec:m-sim}).\claim{S2}
Across four eviction policies and two session models, the dependence of the agentic
marginal on the reachable set holds in 7 of 8 combinations, the exception being W-TinyLFU,
and the net effect of adding the agentic class changes sign with the
policy.\claim{S2}\claim{S5}
If this holds on real systems, the cost of a class depends on the state and on the policy of
the cache, and an estimate of P2 would have to be made for the cache as it is
configured.\claim{S2}\claim{S5}\claim{D5}

% "We did not find prior work": docs/VERIFICHE-chiuse.md (systematic search, 2025-2026) and
% docs/UNDERTOW-CONTESTO.md §7; not a claims.md row.
We did not find prior work that jointly measures, in one shared cache, the marginal origin
cost of one more request of a class, its dependence on the width of the class's reachable
set, the overlap between classes as a controlled variable, and the effect on the tail
latency of the other classes.
Whether admission, placement and priority can move from deciding on identity to deciding
on state and cost is the question these implications open.\claim{D1}\claim{D3}
