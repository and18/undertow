Web infrastructure increasingly treats traffic by its class: human, crawler or AI agent.
We ask whether a class has a cost such decisions can rely on. On a testbed with a
shared Varnish cache in front of a database-backed site, we measure the origin work
caused by one more request of a class while the other classes stay fixed. A traffic class
does not have a stable marginal cost independent of the state of the shared cache,
although a crawler-like class stays flat. With
the same label, volumes, cache and corpus, the marginal cost of agentic traffic changes
sign with the set of objects it can reach: $-0.035$, $+0.143$ and $+0.421$ origin requests
per request at 0.19, 0.58 and 1.90 times the cache capacity. A negative marginal is not a
saving: adding the class costs 1.10 origin requests per second. The measured cost
also shifts by 0.80 to 0.93 origin requests per second with the overlap between classes,
and human tail latency grows with origin load while the human miss ratio barely moves. At
our operating point, blocking agents as well as crawlers costs 2,807 served requests for
no measurable latency gain. Identity alone can be insufficient for
class-sensitive decisions.
