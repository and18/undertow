Web infrastructure increasingly treats traffic by its class: human, crawler or AI agent.
We ask whether a class has a cost decisions can rely on. On a testbed with a shared
Varnish cache in front of a database-backed site, we measure the origin work caused by one
more request of a class while the other classes stay fixed. In our testbed the marginal
cost of a class is not a stable property of its label: for agentic traffic it depends on
the state of the shared cache, while a crawler-like class stays flat. Under the same label,
the marginal cost of agentic traffic changes sign with the set
of objects it can reach: $-0.035$, $+0.143$ and $+0.421$ origin requests per request at
0.19, 0.58 and 1.90 times the cache capacity. A negative marginal is not a saving: adding
the class costs 1.10 origin req/s. The measured cost also shifts by
0.80--0.93 origin req/s with the overlap between classes, and human tail latency
grows with origin load while the human miss ratio barely moves. A characteristic-time model
reproduces these values post hoc, so the effect is structural rather than a testbed
artefact. Identity alone can be insufficient for class-sensitive decisions.
